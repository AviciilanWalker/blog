# Vibe Coding 入门：让 AI 帮你写代码

> 2025 年，Andrej Karpathy 造了一个词叫"Vibe Coding"——你不是在写代码，你是在"描述你想要什么"，然后 AI 帮你写。这篇文章带你从零上手这套全新的开发范式。
> 预计阅读时间：25-30 分钟。

---

## 什么是 Vibe Coding？

2025 年初，前 OpenAI 联合创始人、前 Tesla AI 总监 Andrej Karpathy 在推特上发了一句话：

> "There's a new kind of coding I call 'vibe coding', where you fully give in to the vibes, embrace exponentials, and forget that the code even exists."

翻译过来大概是：**有一种新的写代码方式，我叫它"感觉编程"——你完全跟着感觉走，拥抱指数增长，甚至忘记代码的存在。**

听起来像开玩笑，但他说的是真的。

Vibe Coding 的本质是：**你用自然语言描述想要什么，AI 生成代码，你审查结果，不行就继续描述、让 AI 改，直到满意。** 你不再逐行敲代码，而是像一个产品经理在跟程序员沟通——只不过这个程序员是 AI，而且响应速度以秒为单位。

---

## 为什么 2026 年这件事变得可行了？

Vibe Coding 不是突然冒出来的。它是几个条件同时成熟的结果：

1. **模型能力够了**：2026 年的 Claude Fable 5、DeepSeek-V4、GPT-5.x 在代码生成上的准确率已经足够高。SWE-bench Verified（真实 GitHub issue 修复）的通过率从 2024 年的 ~30% 飙升到 2026 年的 ~95%。

2. **工具链成熟了**：Cursor、Windsurf、Claude Code、GitHub Copilot 这些工具不再是"高级自动补全"，而是能理解整个项目上下文、跨文件修改、自主调试的协作伙伴。

3. **成本降下来了**：2024 年用 AI 写一个中型功能可能要花几十美元 API 费，2026 年同等任务可能只要几毛钱——甚至很多工具提供按月订阅随便用的模式。

4. **开发者心态变了**：新一代开发者不再觉得"手写每一行代码"是技术能力的证明。用 AI 写代码就像当年从汇编切换到高级语言——不是"偷懒"，是"把精力花在更有价值的地方"。

## 主流工具一览

2026 年 Vibe Coding 的工具生态已经分化成几个流派：

| 工具 | 类型 | 适合谁 | 价格（2026） |
|------|------|-------|-------------|
| **Cursor** | AI-native IDE | 全栈开发者 | $20/月 |
| **Windsurf** | AI-native IDE | 偏好流畅体验的开发者 | $15/月 |
| **GitHub Copilot** | IDE 插件 | 已有 VS Code/JetBrains 工作流的人 | $10/月 |
| **Claude Code** | 终端 Agent | 命令行重度用户、后端开发 | 按 token 计费 |

| **Bolt / Lovable** | 全栈应用生成 | 非技术背景、快速原型 | $20-50/月 |

**怎么选？**

- 如果你是**前端开发者**，Cursor 或 Windsurf 上手最快——你改 UI，AI 帮你写组件。
- 如果你是**后端或全栈**，Claude Code 在终端里直接改代码、跑测试、修 bug 的体验极其流畅。
- 如果你**完全不会写代码**但想做一个应用，Bolt 或 Lovable 可以让你用自然语言描述一整个应用，它帮你生成前后端代码并部署。

## 核心工作流：描述 → 生成 → 审查 → 迭代

Vibe Coding 不是"把需求扔给 AI，喝杯咖啡回来收代码"。实际工作流更像是这样的循环：

### 第一步：描述（Prompt）

给 AI 一个清晰的、有边界的任务描述。好的 prompt 包含三要素：

```
我要在 src/utils/ 下新建一个 date.ts 文件，
里面导出三个函数：
1. formatDate(date, format) — 把 Date 对象转成指定格式的字符串
2. daysBetween(d1, d2) — 计算两个日期相差多少天
3. isWeekend(date) — 判断是否周末

要求：
- 用 TypeScript
- 不依赖任何第三方库
- 写好 JSDoc 注释
```

不好的 prompt：

```
帮我写个日期工具函数
```

——太模糊，AI 不知道你要什么格式、什么输入输出、放哪个文件。

### 第二步：生成

AI 生成代码。你看着它一行行往外蹦。

这时候你不需要逐行检查语法——AI 的语法很少出错。你要看的是：
- 逻辑对不对？
- 边界情况处理了吗？
- 风格和项目一致吗？

### 第三步：审查（Review）

生成完了，快速扫一遍。重点关注：

- **空值处理**：传 `null` 或 `undefined` 会崩吗？
- **类型安全**：TypeScript 类型定义合理吗？
- **副作用**：函数会不会意外修改了传入的参数？
- **可读性**：变量名有意义吗？逻辑清晰吗？

### 第四步：迭代

不满意？直接说：

```
第二个函数返回值改成"x 天 y 小时"的格式，还有如果传了无效日期要抛异常
```

AI 会基于刚才的上下文（它知道文件在哪、函数叫什么）直接修改。你不需要重新描述整个需求。

然后再次审查 → 再次迭代 → 直到满意。

**关键原则：你永远是最后一道关。** AI 生成的代码你敢直接上生产，那叫赌博。Vibe Coding 的正确姿势是"AI 写初稿，你来把关"。

## 写好 Prompt 的五个技巧

Vibe Coding 的质量上限，很大程度取决于你 prompt 的质量。

### 1. 给上下文，不只给指令

```
❌ 差：写一个登录页面

✅ 好：写一个登录页面，用 React + TypeScript，样式用 Tailwind CSS。
       组件放在 src/components/Login.tsx。
       包含邮箱输入框、密码输入框、登录按钮、"忘记密码"链接。
       参考项目中已有的 Button 和 Input 组件的写法。
```

### 2. 用"约束"替代"自由发挥"

```
❌ 差：优化这段代码

✅ 好：优化这段代码的性能。重点看：
       1. 有没有不必要的重复计算
       2. 数组操作能否用更高效的方法
       保持原有 API 不变，所有现有测试必须通过。
```

### 3. 一次一个任务

```
❌ 差：帮我重构整个 auth 模块，然后加上 OAuth 登录，然后写测试，再更新文档

✅ 好：（分四轮对话）
       第1轮：重构 auth 模块，提取公共逻辑到 base.ts
       第2轮：在重构后的基础上添加 Google OAuth 登录
       第3轮：给新增的 OAuth 逻辑写单元测试
       第4轮：更新 README 里的登录说明
```

AI 一次处理太多任务容易顾此失彼。拆小、拆细、逐步推进。

### 4. 提供"好的标准"

```
✅ 好：写一个 useDebounce hook。参考项目中已有的 useThrottle 的写法风格。
       要求：TypeScript 严格模式、用 Vitest 写测试、支持 leading/trailing 选项。
```

告诉 AI "参照什么"比从零描述更高效。

### 5. 把报错直接贴给 AI

```
跑了一下，控制台报这个错：
TypeError: Cannot read properties of undefined (reading 'map')
出现在 UserList.tsx 第 34 行。
帮我分析原因并修复。
```

AI 读报错的能力非常强。不要自己 debug 半天，直接把错误信息和相关代码贴给 AI。

## 常见坑和避坑指南

### 坑 1：生成完直接跑，不看代码

AI 偶尔会写出"看起来能跑但逻辑有微妙错误"的代码。比如日期计算差了一天，或者边界条件处理反了。**至少快速扫一遍核心逻辑。**

### 坑 2：无限迭代，越改越糟

改了五轮还是不满意，AI 开始"瞎改"——在无关的地方加代码、删掉之前正确的部分、引入新的 bug。**这时候正确的做法是：回退到最后一版满意的，换一个角度重新描述需求。**

### 坑 3：上下文太长，AI 开始"遗忘"

一次对话超过几百行代码后，AI 会忘记你一开始说的约束。**大任务拆成小会话，每次只关注一个模块或一个文件。**

### 坑 4：过度依赖，丢失编程能力

用 AI 写了三个月代码，关上 AI 发现连 for 循环语法都忘了——这不是危言耸听。**Vibe Coding 的正确姿势：AI 写的时候你要看懂它在写什么。不懂的地方停下来学，而不是跳过。**

### 坑 5：敏感信息泄露

不要把公司私有代码、API 密钥、数据库密码贴到云端 AI 工具里。**用本地模型（如 Ollama + Qwen-Coder）处理敏感代码，或者至少确认工具的数据使用政策。**

## 什么时候适合 Vibe Coding，什么时候不适合？

| 适合 | 不适合 |
|------|--------|
| CRUD 页面和接口 | 核心算法（排序、加密、协议实现） |
| 样板代码（配置文件、类型定义） | 性能敏感的底层代码 |
| UI 组件和布局 | 需要深入领域知识的业务逻辑 |
| 单元测试 | 安全相关的代码（认证、授权） |
| 代码重构（改命名、提取函数） | 你完全不懂的领域 |
| 快速原型和 MVP | 已有复杂代码库的深度修改 |

一个有用的判断标准：**如果让你自己写，你清楚地知道"正确的结果长什么样"，那就可以让 AI 写。如果你自己也不知道正确答案是什么，AI 更不可能知道。**

## 动手：15 分钟 Vibe Coding 实操

假设你电脑上已经装了 Node.js。我们不用任何付费工具，直接用免费方案体验一次完整的 Vibe Coding。

### 第一步：选一个免费工具

- 如果你有 VS Code，装 **GitHub Copilot 免费版**（每月 2000 次补全）
- 或者直接用浏览器打开 **v0.dev**（Vercel 的前端生成工具）
- 或者装 **Claude Code**（Anthropic 的终端工具，有免费额度）

### 第二步：想一个简单项目

比如："做一个浏览器本地运行的番茄钟，25 分钟工作 + 5 分钟休息，能记录今天完成了几轮。"

### 第三步：写 prompt

```
用纯 HTML/CSS/JS（单文件）做一个番茄钟：
- 默认 25 分钟倒计时
- 开始、暂停、重置三个按钮
- 倒计时到 0 时播放提示音
- 显示"今天已完成：X 轮"
- UI 简洁好看，移动端适配
```

### 第四步：迭代

AI 生成第一版 → 你打开看效果 → 哪里不好直接说：

```
倒计时字体太小了，改成 48px；按钮间距加大；背景色太刺眼，换个柔和点的
```

重复几轮，直到满意。

## 总结

Vibe Coding 改变了写代码的姿势，但没改变写代码的本质：**你需要知道什么是好代码，才能让 AI 写出好代码。**

- AI 是你的"超级实习生"——干活快、不知疲倦，但需要你把关
- 你的角色从"打字员"变成了"架构师 + 审查者"
- 描述需求的能力（prompt engineering for code）会成为和写代码本身一样重要的技能

2026 年，不会用 AI 写代码的人正在成为新的"不会用搜索引擎的人"——不是不能干活，是效率差了一个数量级。
